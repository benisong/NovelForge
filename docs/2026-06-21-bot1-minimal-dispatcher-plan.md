# 2026-06-21 Bot1 最小调度器实现方案

## 目标

在现有 `Bot1` / 总纲工作流已拆分的基础上，补一层**最小调度器**，让系统能够稳定判断：

- 当前请求属于普通章节规划，还是总纲设计 / 修正
- 普通章节规划何时触发 `bot1_1` 做近期规划提炼
- 长期维护链 `bot4 / 4_1` 在什么阶段节点触发
- Bot2 在写作前如何强制经过可见写作包裁剪层

本方案优先追求**路径明确、实现简单、状态可控**，不追求第一版就做成复杂智能调度。

---

## 一、当前基础（已完成）

当前代码中已经具备以下前提：

### 1. 显式模式分流
- `outlineMode = "" | "design" | "revise"`
- `Planning.vue` 已按模式切换：
  - 普通章节规划 → `/api/bot1/chat`
  - 总纲设计 / 修正 → `/api/bot1/outline-chat`

### 2. 正式总纲 / 草稿总纲分离
- `currentOutline` = 正式总纲
- `outlineDraft` = 总纲草稿
- 提交 / 放弃 / 离开拦截已落地

### 3. 主流程入口已收口
- 创建项目后默认进入总纲设计
- 写作 / 审核 / 下一章规划等流程已要求：
  - 正式总纲存在
  - 当前章节大纲存在（在对应流程需要时）
  - 当前不处于总纲工作流中

因此，当前真正缺的不是“模式切换”，而是**模式之上的调度与裁剪层**。

---

## 二、最小调度器的职责

第一版调度器只做四件事：

### 1. 模式路由
根据当前项目状态判断本轮请求属于：
- 普通章节规划链
- 总纲工作流链

### 2. 阈值计数
在普通章节规划链中累计：
- user 轮数
- 字数
- 显式收束意图

达到阈值时触发 `bot1_1`。

### 3. 上下文裁剪
在每次结构更新后执行：
- 保留结构层
- 折叠旧长原文为摘要层
- 只保留短窗原文层

### 4. 阶段节点触发
在章节完成 / 写审改闭环完成等节点上，允许触发：
- `bot4 / 4_1`
- Bot2 可见写作包裁剪

---

## 三、建议新增的最小状态

第一版不建议把调度器状态塞进太多零散布尔值，而是明确加一组轻量状态字段。

### A. 普通规划计数状态
建议新增：

- `planning_turns_since_extract`
  - 自上次近期提炼后累计的 user 轮数

- `planning_chars_since_extract`
  - 自上次近期提炼后累计的用户字数

- `planning_last_extract_at`
  - 上次近期提炼发生时的消息索引或时间戳

### B. 近期结构状态
建议新增一块中间态：

- `planning_digest`
  - 最近一次普通章节讨论折叠出的摘要

### C. 总纲讨论摘要状态
建议新增：

- `outline_digest`
  - 总纲设计 / 修正过程中，被折叠下来的讨论摘要

### D. 长期阶段状态（可先最小化）
可先不加太多复杂状态，只在章节保存节点判断：
- 当前章节是否完成
- 是否需要触发长期维护

如果第一版要记忆化，可新增：

- `chapters_since_memory_maintain`

---

## 四、调度主流程

### 情况 A：`outlineMode in ["design", "revise"]`
直接进入总纲工作流：

1. 使用 `/api/bot1/outline-chat`
2. 输入上下文：
   - `outlineDraft`
   - `currentOutline`（仅 revise 作为基线）
   - `outline_digest`
   - 最近短窗原文
   - 当前用户输入
3. 输出：
   - assistant 回复
   - 更新 `outlineDraft`
4. 若本轮草稿发生明显更新：
   - 将旧长讨论折叠进 `outline_digest`
   - 保留新的 `outlineDraft`
   - 仅保留短窗原文
5. 不触发 `bot1_1`
6. 不触发 `bot4 / 4_1`

### 情况 B：`outlineMode == ""`
进入普通章节规划链：

1. 使用 `/api/bot1/chat`
2. 输入上下文：
   - `currentOutline`
   - `chapterOutline`
   - `planning_digest`
   - 最近短窗原文
   - 当前用户输入
3. 输出：
   - assistant 回复
   - 更新 `chapterOutline`
4. 更新阈值计数：
   - `planning_turns_since_extract += 1`
   - `planning_chars_since_extract += len(user_input)`
5. 若达到阈值：
   - 触发一次 `bot1_1`
   - 用最近一段普通规划对话 + 现有结构信息生成新的近期提炼结果
   - 更新 `chapterOutline` / `planning_digest`
   - 重置计数器
6. 若未达到阈值：
   - 仅维持 Bot1 当前对话

---

## 五、阈值规则（第一版）

### 普通 Bot1 → `bot1_1`
满足任一条件即触发：

- 连续新增 **4** 轮 user 消息
- 用户输入累计超过 **1200** 字
- 用户明确表达：
  - “整理一下”
  - “收一下”
  - “总结一下”
  - “帮我归纳”
  - “这一段可以定稿 / 成形了”

### 总纲模式
总纲模式下**不启用**上述阈值触发。原因：
- 总纲工作流本身就是显式结构编辑
- `outlineDraft` 已经承担当前结构输出角色

### 长期维护链 `bot4 / 4_1`
第一版仅在以下节点触发：

- 一章正式保存完成
- 一次写作—审核—修改闭环完成
- 或累计 3 章完成后做一次更大的维护

---

## 六、上下文裁剪规则

### 1. 结构层（始终保留）
- `currentOutline`
- `outlineDraft`（总纲模式）
- `chapterOutline`
- `planning_digest`
- `outline_digest`

### 2. 摘要层（折叠旧对话）
- 普通章节规划被提炼后，旧长聊天折叠为 `planning_digest`
- 总纲讨论形成阶段结果后，旧长讨论折叠为 `outline_digest`

### 3. 短窗原文层（维持连续性）
建议只保留：
- 最近 2 条 user
- 最近 2 条 assistant

第一版先不要保留太长，否则又会回到无限增长。

### 4. 裁剪时机

#### 普通模式
当 `chapterOutline` 被一次阈值提炼稳定更新后：
- 折叠参与提炼的旧聊天原文
- 仅保留新结构 + 摘要 + 短窗

#### 总纲模式
当 `outlineDraft` 完成一次明显阶段更新后：
- 折叠旧讨论原文
- 保留新草稿 + 摘要 + 短窗

---

## 七、bot1_1 的第一版职责

### 允许做的事
- 提炼近期章节规划成果
- 稳定当前 `chapterOutline`
- 输出一份较短的 `planning_digest`

### 不允许做的事
- 改 `currentOutline`
- 改 `outlineDraft`
- 参与总纲设计 / 修正

也就是说，第一版 `bot1_1` 是**近期规划稳定器**，不是“第二个总纲器”。

---

## 八、bot4 / 4_1 的第一版职责

### 允许做的事
- 小总结
- 大总结
- 长期记忆压缩
- 为后续阶段保留长期上下文

### 不允许做的事
- 凭空生成正式总纲
- 自动覆盖 `currentOutline`

后续如果需要让 bot4 参与总纲维护，也只能走“提出维护建议”而不是直接改正式版。

---

## 九、Bot2 可见写作包（第一版要求）

### 输入来源
可读取：
- `currentOutline`
- `chapterOutline`
- `planning_digest`
- 必要的长期摘要

### 输出原则
写入给 Bot2 的必须是**当前章可见包**，只包含：
- 当前章节目标
- 当前章节人物 / 冲突 / 背景
- 必须知道的历史信息
- 不会剧透未来的局部结构

### 明确禁止
Bot2 不应直接读取：
- 正式总纲全文原件
- 原始长期记忆全文
- 全量聊天历史

---

## 十、建议的代码落地顺序

### 第一步：调度状态字段
在项目状态模型与前端 store 中补最小调度字段：
- `planning_turns_since_extract`
- `planning_chars_since_extract`
- `planning_digest`
- `outline_digest`

### 第二步：封装上下文构造器
不要继续在 `Planning.vue` 里拼越来越多条件分支。
建议抽一层：
- 普通模式上下文构造
- 总纲模式上下文构造
- 上下文裁剪逻辑

### 第三步：补最小 `bot1_1` 调用路径
可先是同步调用，也可以先是伪后台调用，但第一版重点是：
- 触发时机明确
- 输出落点明确

### 第四步：补阶段节点上的长期维护触发
先接章节完成节点，不急着一次铺满所有节点。

### 第五步：补 Bot2 写作包裁剪层
这是 Bot1 重构真正闭环的最后一步。

---

## 十一、第一版故意不做的内容

为了避免过度设计，第一版先不做：

- 复杂权重评分器
- 自动语义分类到“像总纲还是像章节”的智能路由
- 并行多链竞争
- `bot4` 自动改正式总纲
- 全量长期记忆动态检索

先把最小闭环跑通，再迭代智能度。

---

## 十二、实施完成后的系统口径

完成这一轮后，Bot1 体系应当稳定理解为：

- `Bot1`：当前章节讨论器
- `总纲工作流`：正式总纲编辑器
- `bot1_1`：近期规划稳定器
- `bot4 / 4_1`：长期状态维护器
- `Bot2 package layer`：写作信息防火墙

这时才能算 Bot1 重构真正从“接口拆分”进入“调度成型”。
